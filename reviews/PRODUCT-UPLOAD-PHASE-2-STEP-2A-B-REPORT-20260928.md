## Known limitations in this step

1. Suggestions currently read the existing live `skh.advancedCategories` configuration. The canonical-to-live compatibility bridge is not yet implemented.
2. The UI uses lightweight prompt-based add/edit entry for the first step. A richer inline editor is still needed for production UX.
3. Option-value image attachment UI is not yet implemented; the contract supports image references, but the existing uploader has not yet been connected to each option value.
4. Variant image attachment UI is not yet implemented.
5. Generated variants are stored additively as `variantsStructured`; existing concrete `variantCombinations` and POS identity remain untouched.
6. New product IDs are generated by the existing `addDoc` path, so generated preview variants do not receive final inventory keys until a dedicated identity-compatible follow-up step.
7. Existing Edit Product has not yet reached structured Add Product parity.
8. Buyer showcase has not yet been changed to consume the structured options/variants/features fields.
9. No category can be marked COMPLETE from this step; runtime category coverage remains pending.
