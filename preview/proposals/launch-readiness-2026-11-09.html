4. Hatua za mmiliki (3 + 2 za kawaida)

Hazikufanywa na wakala (zinahitaji credentials zako + uamuzi wa deploy). Mpangilio unaopendekezwa:

O1. Deploy sheria (muhimu zaidi — inafunga uvujaji wa guest)

cd /path/to/SokoHai
firebase deploy --only firestore:rules --project sokonet-3b847

O2. Hakikisha functions zimedepolywa (server ndiyo mamlaka sasa)

firebase deploy --only functions --project sokonet-3b847   # ikiwa escrowRelease/disputeOpen/haipayReleaseLink bado hazipo live (region: europe-west1)

O3. Backfill: safisha false completions za zamani (script tayari)

npm i --no-save firebase-admin
GOOGLE_APPLICATION_CREDENTIALS=/path/to/owner-key.json node tools/g1/owner_backfill_false_completions.mjs
# kagua orodha, kisha:
GOOGLE_APPLICATION_CREDENTIALS=/path/to/owner-key.json node tools/g1/owner_backfill_false_completions.mjs --fix --confirm

O4. Uthibitisho wa malipo halisi (live-IPN)

Fanya muamala mmoja halisi wa PesaPal (kiasi kidogo), thibitisha: escrow_holds → held → shipped → buyer-confirm → wallet_ledger/order_<id>_released ipo + wallet ya muuzaji imeongezeka. Kisha deploy hosting (Netlify) kama kawaida.

5. Hatari zilizokubalika (zisizo matatizo ya launch)

  • userEmail/contact kwenye matangazo ya public — biashara-haja (mnunuzi ampate muuzaji/dereva); inapendekezwa kuhamia userCards-based contact baada ya launch.
  • Admin email hardcoded kwenye rules (rshabansaid@gmail.com) — inafanya kazi lakini ipendekezwe kuhamia custom claims tu.
  • paymentStatus inaandikwa na party (core-tx) — server haiiamini kamwe; paymentVerified ndiyo ukweli.
  • Double-accept ya ombi moja (nje ya double-click) inaweza kuunda oda 2 — ombi huondoka kwenye foleni baada ya kukubaliwa; ukaguzi wa kipekee ni kazi ya server ya baaye.
  • Orodha ya sokopay_links isiyo na kichujio (bila where) inakataliwa (403) — app inachuja kila wakati (where userId/buyerId), hivyo tabia hii ni kinga dhidi ya enumeration, si tatizo.
