7Changamoto na hatari zilizobaki

  1. Minification haiondoi maombi. Bado ni 250. Kila ombi lina gharama ya latensi kwenye 3G. Hii ni hatua inayofuata ya kweli.
  2. Faida ni ndogo kwenye 3G FCP (−0.2%). Sababu: FCP inatokana na CSS/HTML. Kama lengo ni “ukurasa uanze kuonekana haraka”, CSS ndiyo inayofuata.
  3. dist/ haiko kwenye git na hakuna CI. Bila CI, mtu anaweza kusambaza build bila --minify au bila uthibitisho, kimya kimya. Hii ni hatari ya kweli zaidi kuliko minification yenyewe.
  4. Dependency mpya: acorn (devDependency). Build ya kawaida haihitaji; --minify inahitaji. Nimeiweka wazi.
  5. Vitendo vya Firestore kwenye regression: nimeona moja (views). Sikupata nyingine, lakini sipendi kudai hakuna bila kuthibitisha kila handler.
  6. Majaribio 15 ya emulator hayakuendeshwa (hakuna firebase CLI hapa) — pengo la uthibitisho, si uthibitisho wa kosa.
  7. Vipimo ni Chromium kwenye sandbox — si simu halisi wala mtandao halisi wa Tanzania.

8Uamuzi

UAMUZI: IDHINISHA — lakini usiwashe --minify kama default ya production bado.

Lango npm run build:dist:minify liko tayari na linathibitika. Sikuifanya default kwa sababu ulisema “Usibadilishe default production build mpaka ripoti ikaguliwe na kuidhinishwa.”

Hatua inayofuata ninayopendekeza:

  1. CI inayokimbia npm test + build:dist:minify kwenye kila PR. Hii inafanya faida kuwa ya kudumu na inazuia kurudi nyuma.
  2. CSS — ndiyo inayoshikilia FCP. Faili 76, 1,432 KB kwenye dist.
  3. Maombi 250 — hatua yenye faida kubwa zaidi kwa 3G, lakini inahitaji kazi ya moduli-moja-moja (na D1 ilionyesha hatari yake).
